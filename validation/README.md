# 教学算例与跨平台验证规范

本目录保存参考模型记录、验收约定及独立比较程序。教学脚本在 `examples/`，只运行 PyCy_EMT_Lite、解释物理现象、绘制自身波形并按配置保存结果。参考软件运行和跨平台比较放在本目录，不在各教学脚本中重复实现。

本规范适用于后续新增或实质扩展的算例，不要求为形式统一改写全部既有脚本。内部解析解、独立 Python ODE、KCL/KVL、能量和步长细化是必要证据，不能冒充 Simulink/PSCAD 的真实数值结果。现有算例的运行成功也不等于新增算例完成跨平台验收。

## 1. 教学脚本的最小结构

复用 [CaseDefinition](../pycy_emt_lite/cases.py) 和既有 `CaseDefinition → Circuit → Simulator → SimulationResult` 流程。简单算例保持简单；复杂算例按需拆分函数，不新增算例基类、依赖注入或插件系统。

1. 模块说明：学习目标、电路拓扑、预期现象及模型限制。
2. 集中参数：SI 单位、峰值/RMS、线量/相量、正方向、初值及可修改范围。
3. 创建元件：每次运行使用新实例；清楚注明节点、参考地及支路电流方向。
4. 事件与控制：列出实际生效时间、采样/保持、回调时序及 PWM 约定。
5. `SimulationConfig` 与 `CaseDefinition`：明确步长、终点、积分方法及输出配置。
6. 执行、结果摘要和自身绘图：说明主要数值的物理意义及参数练习。
7. 主程序入口：从仓库根目录运行；无保存配置时不产生持久化结果目录。

优先沿用既有 `OutputOptions` 的数据、图像保存和显示选项。保存时 `run_case` 输出 `result.csv`、`result.json`、`result.npz`；JSON/NPZ 可保留事件及元数据，CSV 需配套记录。教学脚本不加载商业软件、不查找本地第三方模型、不自动下载参考、不绘制参考叠图。图标题、坐标轴、摘要和文档中的单位及方向应一致。

## 2. 文件职责

```text
examples/                         PyCy 教学脚本
validation/
  common/                         可复用的数值比较工具
  cases/<case_id>/
    manifest.json                 来源、证据状态、限制与冻结验收条件
    parameters.json               两平台物理/控制/求解参数映射
    signal_mapping.json           可选；也可在 manifest.signals 中直接列明
    export_reference.m            可选；本例的 MATLAB 导出脚本
    compare.py                    读取真实结果、计算指标、输出图与报告
    README.md                     本例复现命令、接线、差异和结果状态
local_reference/<case_id>/         默认由 .gitignore 排除
  simulink/                       本地参考工程与必要修改副本
  pscad/
  raw_results/                    原始模型输出与原始日志，不覆盖
  normalized_results/             确定性单位/列名转换后的副本
  comparison_results/             PyCy 数据副本、图、指标和运行证据
```

仅创建本例实际需要的文件和子目录。不为所有例强制增加空导出器；若 `manifest.json` 已包含完整映射，则不重复维护第二份映射。上述记录格式先采用简单 JSON/Markdown；当前公共工具不等于通用 manifest 校验器，也不自动证明来源或许可。

PyCy 默认保存仍可使用 `outputs/<case_name>/`。开始一次正式比较时，将本次候选结果复制到唯一的本地运行目录，记录 hash 和源码提交，避免后续教学运行覆盖证据。参考原件、导出副本和报告应有可区分的运行编号。

## 3. 真实证据状态

状态必须附带日期、来源、文件/日志路径及限制；不能仅更改一个状态单词。

| 状态 | 最低证据 | 不能据此宣称 |
|---|---|---|
| `discovered` | 已找到具体模型/真实数据来源、名称和适用版本 | 已下载、可运行或已有参考结果 |
| `downloaded` | 本地取得的确切文件、来源、版本、字节 hash | 模型拓扑等价或许可允许再分发 |
| `inspected` | 实际检查工程结构、参数、初值、控制及依赖，并记录差异 | 实际完成参考仿真 |
| `runnable` | 在记录的软件/工具箱/许可环境中真实完成本模型运行，有日志和退出状态 | 已导出足够信号或候选通过验收 |
| `reference_ready` | 本地真实运行或可信发布者提供的真实数值结果；模型身份、配置、信号、单位、时间轴及数据 hash 可核验 | PyCy 比较已通过 |
| `validated` | 候选内部测试及真实跨平台比较通过冻结标准，报告、图和结果可追溯 | 全部教学、回归、Git 交付工作已完成 |

可信发布数据路径可以直接形成 `reference_ready`，但要注明“未在本机重跑”，提供真实发布结果与对应模型/参数的关联证据。网页截图、文档中的示意曲线、安装路径、软件启动成功、`load_system` 成功以及公开教程本身均不足以成为 `reference_ready`。

证据状态与 [tasks.json](../docs/development_roadmap/tasks.json) 的任务状态分开。缺少真实结果时，内部验证工作可以独立完成，整个新增算例仍保持待验证或受阻。更新 [validation_status.md](../docs/development_roadmap/validation_status.md)，记录下一步可直接执行的命令，不把环境受阻误写为模型不可能实现。

## 4. 来源、许可与运行记录

每个参考至少记录：模型/数据名称及 ID、来源页和实际下载地址、访问日期、软件与模型版本、文件 hash、所需工具箱/编译器、运行命令、求解器及步长/容差、初值、输出设置、操作系统、运行日志和实际结果。

下载许可、修改许可及再分发许可应分别核对。可公开访问不自动授予再分发权。第三方模型、商业工程和真实输出默认留在忽略的 `local_reference/`；仓库提交来源链接、复现说明、自有脚本和必要的小型结果摘要。没有明确再分发依据时不提交第三方原件；引用发布数据也记录其使用条件。自写导出脚本不能自动改变被调用模型或输出的许可。提交前检查实际暂存范围。

允许的等效简化必须列出修改前后拓扑、方程与参数，以及对验收量的影响。桥臂外控双向电阻开关不能登记为自动二极管；固定阻抗不能登记为恒功率负荷。物理模型差异先明确，不直接归因于数值求解器。

建议每次本地运行另存 `run_record.json`，包括：

| 记录项 | 内容 |
|---|---|
| 身份 | `case_id`、参考模型 ID、证据状态、运行时间和运行编号 |
| 软件 | PyCy Git SHA/工作区状态、Python/依赖版本、参考软件/工具箱版本 |
| 输入 | 参数和验收 manifest 的 SHA-256；原始模型与修改副本的 SHA-256 |
| 运行 | 实际命令、运行目录、成功/失败、退出码、日志路径、配置和限制 |
| 产物 | 原始/归一化/候选数据、转换脚本、指标和图片的路径与 SHA-256 |

SHA-256 标识的是确切字节，不能单独证明数据来自某款软件。Windows 可用 `Get-FileHash -Algorithm SHA256 -LiteralPath <path>`，其他平台可使用 Python `hashlib`；同时保留来源与真实运行链路。不要把 hash 值当作独立的真实性证明。

## 5. 在候选实现前冻结验收

每例先写验收约定并留下 Git 或带日期的记录，再编写候选。至少包括：

- 电路结构、参考软件模型、模型差异及参数映射；交流相序/相角、变比定义、P/Q 及端口电流正方向。
- 电容电压/电感电流、控制积分器、PLL、机械状态等初值；稳态初始化与从零启动是否一致。
- 事件时间、边沿左右侧约定、控制采样/保持、PWM 载波相位和开关电阻；两平台输出采样与求解步长。
- 每个对比信号的列名、单位、方向、工程基准、比较时间窗、事件保护间隔及指标上限。
- 预期物理现象，例如充放电方向、故障施加/清除、电流连续、主振荡频率、功率方向和基波相位。

优先使用适合该现象的均值、RMS、基波相位、峰值、频率、纹波或阶跃特征，辅以 RMSE、NRMSE 和最大绝对误差。NRMSE 的分母必须明确；公共工具使用预先指定的正工程基准 `scale`，不以结果的峰峰值或拟合幅度临时归一化。各信号应保留物理单位的绝对上限，避免基准掩盖小量错误。

不要求每个例机械地使用所有指标。若只用波形误差不足以判定控制/功率正确，则增加对应特征与内部守恒断言。开关级例可以预先选择周期平均、基波或包络，不能在看到差异后改用更容易通过的指标。

验收条件确需修正时，保留失败结果、说明原约定的错误或新证据、版本化修改并重跑双方，不能看到结果后随意放宽阈值、删去困难窗口或忽略功率方向相反等错误。

## 6. 原始数据与归一化

`raw_results/` 保留原始格式、时间戳、信号、精度及软件日志，不修改原件。`normalized_results/` 保存确定性转换副本和转换说明：输入 hash、脚本版本、列名映射、明确的单位换算/符号换算、时间原点和输出 hash。原始与归一化文件分别计算 hash；CSV 换行或数值格式变化也会改变字节 hash。

标准化后时间单位为 s，值使用已声明的 SI 单位；保留原始时间点。对比前拒绝缺列、非有限值、未处理的重复或倒序时间、覆盖不足。不得静默丢失重复时刻；参考输出若有事件左/右双值，原始文件保留双方，标准化明确选取哪一侧，连续比较窗口避开受影响区间，或由专用事件比较器处理。不得外推缺失数据，不得平滑或滤波来隐藏差异。确需抗混叠/抽取时，必须事先约定，并保存原始波形及明确算法。

时间零点由模型定义与导出方式确定。只有可追溯的单位转换或预先声明的绝对时间原点转换可用于归一化，**禁止为验收拟合任意时移、互相关最佳延迟或相位补偿**。允许另作诊断性延迟分析，但诊断曲线不得用于正式通过判定，正式报告保留原时间轴和失败指标。

## 7. 公共比较工具及边界

[common/comparison.py](common/comparison.py) 目前提供 `SignalSpec`、`aligned_signal` 和 `compare_signals`，用于**连续分段窗口**：

- 检查有限、严格递增时间，拒绝越界外推；保留绝对时间，不拟合幅度或延迟。
- 在双方时间点与窗口端点的并集上作分段线性插值。
- 按真实时长积分均值、RMS 和误差；RMSE 对分段线性误差的平方积分，避免非均匀密采样区占不合理权重。
- 计算并报告绝对最大误差，按 `SignalSpec` 中固定的 NRMSE 和绝对上限共同判定。
- 若结果对象带 `event_log`，拒绝穿越事件所在采样区间的连续比较。

该工具不自动检测 CSV 中未记录的事件，不是开关跳变重建器，也不提供基波/谐波或控制特征的通用验收。每例必须检查参考事件，显式划分窗口，必要时采用专用事件/频谱指标。不能将真实开关沿用一条线性斜线平滑后宣称开关时序正确。

本例 `compare.py` 负责读取 manifest 和信号映射、核对文件与运行记录、逐窗调用工具、保存指标和独立对比图，并在未满足标准或缺少真实参考时返回失败状态。库函数算得出一份报告不等于已完成这些来源核验。图与报告应列明参数/参考身份、绝对时间轴、单位、窗口及通过/失败；保存全波形以便看到被保护间隔排除的边沿。

## 8. 正式完成条件

新增算例只有在实现、内部物理验证、独立运行、真实 Simulink/PSCAD 参考确认、冻结条件的跨平台比较、图与结果保存、必要自动化测试、教学说明以及 Git 提交均完成后，才能记为 `completed`。代码和内部测试已通过但参考运行受阻时，应明确记录为候选或待验证，不计入正式完成数量。

常规测试不要求 CI 具备商业软件许可。公共比较工具使用有明确解析性质的合成数据测试数值行为，并清楚标注其测试用途；合成数据不能进入真实参考目录充当商业软件结果。真实参考回归仅在具备合法软件/数据时执行，始终记录本轮实际环境与产物，不能拿历史通过记录代替当前执行。

实施与恢复顺序见 [路线图](../docs/development_roadmap/04_long_term_roadmap.md)、[验证状态](../docs/development_roadmap/validation_status.md) 和 [下一步](../docs/development_roadmap/next_actions.md)。
